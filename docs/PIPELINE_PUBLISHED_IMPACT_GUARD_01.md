# PIPELINE-PUBLISHED-IMPACT-GUARD-01：加工保存时已发布绑定影响确认（2026-10-16）

## 本批交付

在现有数据加工 `PUT /api/datasets/{id}/pipeline` 保存链路上，增加一个**受控、需要显式确认的已发布组件变更门禁**。仅当目前已发布分析主题的 V2 Widget 明确满足 `datasetId` 与加工数据集相同、`usePipeline=true`、`pipelineRevision` 等于当前待修改的加工版本时，保存新版本才可能使它变成旧版本。

- 编辑器点击“保存步骤”后，先访问新增的 `GET /api/datasets/{id}/pipeline/change-impact?revision=N`。接口只读元数据库，返回当前修订版本、已发布的受影响分析主题和组件数量，以及根据当前发布快照计算的短期确认指纹。没有受影响的已发布组件时继续原保存流程，不弹窗、不附加确认字段。
- 有受影响组件时，页面显示分析主题名称与组件数量，明确提示保存后旧版本绑定需手动检查并重新发布。用户取消则不执行 PUT。用户确认后只发原有 `steps`、`revision`，额外带 `acknowledgePublishedImpact=true` 和 `impactToken`；**不传任意 SQL、接入凭据或自由权限规则**。
- **服务端是最终门禁。** 它在原先 `@Transactional` 保存方法里重新查询已发布快照，校验确认标志和基于目标数据集 ID、当前修订号、真实已发布报表内容生成的 SHA-256 指纹。省略确认、伪造指纹或发布快照变化均拒绝保存；原 SQL Compiler、稳定字段约束、JOIN 基数确认、乐观版本更新规则均保持有效。
- 未保存的新加工链以及所有已发布组件已绑定更旧的版本时，不需要重复确认。本次操作不自动更新或重发布任何分析主题，避免未经授权的变更传播。
- 单次最多检查 200 个已发布分析主题，每个快照最多 150 个 Widget、300 KB；不能解析的已发布快照采取保守拒绝保存，不会误报“无影响”。扫描不打开 StarRocks/MySQL 业务数据源，也不触发预览查询。

## 专项验收

- `PipelineChangeImpactTest`：使用 H2 的真实加工版本保存与分析主题元数据，确认未确认拒绝、伪造标识拒绝、发布快照改变导致过期确认拒绝、有效确认成功升级、旧发布绑定无需重复确认，并验证无影响场景。
- `AnalysisPipelineApiTest`、`AnalysisPipelineJoinTest` 和既有编译器测试：保持旧加工 API 和 JOIN 参数/风险规则兼容。
- `frontend/npm run build`，Chromium `scripts/pipeline_editor_browser_smoke.cjs` 覆盖已发布主题的确认弹窗；CAST 和 JOIN 浏览器原测试补齐无影响查询响应，继续覆盖旧保存流程。
- CI：`.github/workflows/pipeline-editor-scoped.yml`。只在 CI 成功后标记远端验收通过。不进行全量回归，不自动部署 18130 或 18110。

## 边界说明

本批是对既有“单数据集加工版本绑定”进行保存确认，不是审批流或权限角色系统；只有管理员页面能操作原加工编辑。指纹用于防止过期确认，不是用户身份认证或数据库事务外的全局一致性保证；如果在数据库只读事务隔离级别不足时发生极窄的并发发布与保存竞争，仍应结合已有发布权限/版本门禁处理。未实现多个源表构成的完整版本化语义模型、自动影响修复或跨数据集授权审批。

开发机 `18130` 预览实例和 `18110` 原服务保持原样；本批修改只提交开发分支。
